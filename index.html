Apollian with a Twist

拆解 Shadertoy Wl3fzM(CC0)。只有一个 2D 画面,却用到了折叠、球反演、第四维、一块“地板”和两盏灯。每一步都可以拖动、调参。

拖动平移,滚轮缩放。这是对原作的 WGSL 移植(下方有对照),所有常量都做成了可调参数。

需要支持 WebGPU 的浏览器(新版 Chrome / Edge / Safari)。离开视口的画面会自动暂停。

0 · 总览:一帧是怎么来的

先建立直觉。画面里彩色发光的曲线,是一个 4D 分形被一个 2D 平面切开后得到的“零等值线”。曲线之外的黑色区域,是曲线投射在下方一块地板上的阴影,由两盏灯照出来。整个过程可以分成两半:

df(p)
p → 距离 d→ weird()
2D 点抬到 4D、旋转、缩小→ apollian()
折叠 + 反演 ×7
color(p)
相机射线 → 地板→ 两盏灯
回到曲线平面取 d→ 彩虹色 + 辉光
按到原点的距离上色→ postProcess
gamma / 对比度 / 暗角

★ 一步步搭出画面

先不管内部怎么算,看最终画面是怎么一层层叠出来的。点下面的按钮(或用“上一步 / 下一步”)逐步显示;每一步只增加一件事,右边是这一步对应的代码含义。

后面的 1–7 节,就是把这 8 步里的黑盒——尤其是第 ② 步 df(p) 和第 ⑥ 步地板上的光——一个个打开。

1 · 折叠

apollian() 每一轮的第一行:

p = -1.0 + 2.0*fract(0.5*p+0.5);

这是周期为 2 的锯齿波:把任意点平移回 [-1, 1] 的盒子里(四个分量各做一次)。等价于把空间切成 2×2 的格子,每个格子里放同一份内容。注意是 fract 平移,不是 abs 镜像,所以每个格子同向复制。

拖动粉色点,青色点是它折叠后的位置,一定落在蓝框里。黄色图案在每个格子里都一样。

2 · 球反演

float r2 = dot(p,p);
float k  = s/r2;      // s = 1.2
p       *= k;
scale   *= k;         // 记录累计的放大倍数

点 p 被换成 s·p/|p|²:球内和球外互换,而且圆映成圆(穿过原点的圆变成直线)。越靠近原点放大得越多,所以 k 常常远大于 1。四个分量一起参与,即反演发生在 4D 里,下图只是 2D 的类比。

拖动白色句柄。橙色圆 → 金色像;紫色直线 → 粉色像。蓝色虚线是反演球。试试把橙色圆拖到原点附近,看它被放大多少。

3 · apollian:迭代与距离

把“折叠 + 反演”重复 7 次(原作固定写死 7,这里可调),然后:

return abs(p.y)/scale;

迭代结束时的 p 处在最深一层的坐标系里,那里只放了一个最简单的形状:平面 y = 0,它的距离就是 |p.y|。每次反演都把长度放大 k 倍,回到原空间要除以累计的 scale,所以这是一个距离估计。一个平面,经过逐层折叠 + 反演,就变成了布满圆的分形。

因为是 abs,返回值永远 ≥ 0:没有“里面”,只有零集(曲线)本身。下图用等值线显示 d,白色是曲线。把迭代次数从 0 拖到 7:0 次是一条直线;每多一次,圆里就多一层圆。

点一下图,查看这个点的迭代轨道。


        
拖动平移,滚轮缩放。点击图上一点,右边列出这一点每一轮的全过程:折叠前 → 折叠后 → r² → k=s/r² → 反演后 → 累计 scale → 此时的距离估计 di = |p.y| / scale。把迭代次数拖到不同值,看 di 怎么逼近真实距离。

      

    

  


  
怎么读这张表:选一个靠近曲线的点,看 di 一栏——每多迭代一轮,di 往往变得更小、更准(因为 scale 越来越大,同样的 |p.y| 对应的真实长度就更小)。选一个远离曲线的点,di 则几乎不变。r² 一栏很小的那些行(k 很大)就是“钻进了小圆里”的那几轮。


  
4 · weird:第四维的 twist

  
apollian() 吃的是 vec4。屏幕只有 2D,weird() 要负责把 2D 点“编织”成一个 4D 点:

  
vec4 off = vec4(r*PSIN(tm*sqrt(3.0)), r*PSIN(tm*sqrt(1.5)), r*PSIN(tm*sqrt(2.0)), 0.0);
vec4 pp  = vec4(p.x, p.y, 0.0, 0.0) + off;     // z 分量由 off 提供
pp.w = 0.125*(1.0 - tanh(length(pp.xyz)));      // 第四维 = 随半径衰减的“鼓包”
pp.yz *= ROT(tm);                               // 3D 里的旋转
pp.xz *= ROT(tm*sqrt(0.5));
pp /= z;                                        // z = 4

  
    
    
  • off:三个频率 √3、√1.5、√2 互不成有理比的正弦,让切面的位置永远不会精确重复地在 4D 里漂移(只改 xyz,不改 w)。
    • 
    
  • w 鼓包:中心 w≈0.125,往外趋于 0。所以屏幕上不同半径处,切的是 4D 分形的不同“高度”。这是“twist”的一半。
    • 
    
  • 两个旋转:作用在 yz、xz 平面,把 z 方向(以及漂移)混进 xy,让切面在 4D 里缓慢转动。另一半 twist。
    • 
    
  • 开头还有一行 p *= ROT(TIME*0.1),让整幅图在屏幕上缓慢旋转。
    • 
  

  
下面可以“冻结”动画,手动控制切面位置。把 w 鼓包设成 0、旋转关掉,就退化成普通的 3D Apollonian 的一个切片。

5 · 两层缩放:z 与 zoom

  
有两个容易混淆的缩放:

  
float df(vec2 p) {
  const float zoom = 0.5;
  p /= zoom;                  // 把图放大 2 倍
  return weird(p) * zoom;     // 距离也要按比例缩回来
}
...  pp /= z;  ...  return d*z;   // weird 内部:z = 4

  
z 决定从分形里取多大的一块(z 越大,取的区域越小,但又被反演放大,图案越稠密);zoom 只是 df 的外部缩放,乘回去保证距离值仍是长度。这个“先除再乘”的写法在整个着色器里反复出现:坐标缩放必须伴随距离反向缩放,否则光线/阴影的几何会错。

  

    

      

      

    

  


  
6 · 地板与两盏灯

  
只有曲线的话,画面是平的。作者加了一块“地板”,让曲线投下阴影,而且是透过曲线平面看到的阴影:

  
    
    
  1. 相机在 (0, 10, 0),俯视。屏幕点 p 对应曲线平面 y=0 上的 pp = (p.x, 0, p.y)。
    2. 
    
  2. 这条射线继续往下,打到另一个平面 y = b = -0.125,得到地板上的点 bp。
    3. 
    
  3. 从 bp 朝两盏灯(高度 1.25,位置 (±0.5, 1.25, 0.5))各发一条射线,必然穿过 y=0 的曲线平面,交点是 sp1、sp2。
    4. 
    
  4. 在这两个交点取 df:sd ≈ 0 说明光线正好穿过曲线(被挡住),sd 大说明穿过空隙(被照亮)。亮度 = (1 − exp(−15·sd)) / 距离²。
    5. 
  

  
所以地板上的光是“曲线图案”经过两次不同方向的投影,再叠起来的结果。因为相机几乎垂直向下,bp 和 pp 差别很小,而 sp1、sp2 会被灯的位置推开,阴影因此相对曲线本体产生视差错位,画面立刻有了“深度”。

  

    

      

      

        
        

        

        
左图是俯视的“只看地板上的光”,点击或拖动选择一个屏幕点:白点是 pp,青点是 bp,黄/粉点是两盏灯穿过曲线平面的位置 sp1/sp2。右上是按真实比例画的侧视图(x–y 投影)。把“地板深度”拉大,视差就非常明显。

        
彩蛋:原作算 sp2 时用了 st1 而不是 st2(应该是笔误)。勾上“修正 sp2”,第二盏灯的投影会和侧视图里画的射线严格对上,画面也会稍有不同;默认保持原作行为。

      

    

  


  
7 · 配色、辉光与后处理

  
float l   = length(p);
float hue = fract(0.75*l-0.3*TIME)+0.3+0.15;     // 按到原点的距离分色相,随时间向外流动
float sat = 0.75*tanh(2.0*l);                    // 中心偏白,外围饱和
col  *= (1.0-tanh(0.75*l))*0.5;                  // 地板光向外变暗
col   = mix(col, bcol, smoothstep(-aa, aa, -d)); // d≈0 的地方盖上彩色曲线,aa 是一个像素宽
col  += 0.5*sqrt(bcol.zxy)*exp(-(10.0+100.0*tanh(l))*max(d, 0.0));  // 曲线两侧的辉光

  
辉光的衰减速度是 10 + 100·tanh(l):中心衰减慢(光晕宽),越往外越窄、越锐利。色相用 bcol.zxy(把颜色通道换位)作辉光色,使辉光和线条本身略有色差。最后 postProcess 依次做 gamma 2.2、S 形对比度、负饱和度(mix(.., -0.4) 其实是拉高饱和)和暗角。
